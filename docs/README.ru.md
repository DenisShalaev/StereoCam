# StereoCam — документация (русский)

[English](README.en.md) · [Deutsch](README.de.md)

> **Статус: build 1. Приложение ещё ни разу не запускалось на телефоне.** Android-код не компилировался (в среде разработки нет Android SDK). На настольной Java проверены только выравнивание пары и запись MPO. Всё, что связано с камерами телефона, — непроверено.

## 1. Что это

StereoCam делает стереофотографию **одним телефоном и одним нажатием**: снимает одновременно двумя задними камерами (например, основной и сверхширокоугольной), выравнивает пару и сохраняет в нескольких форматах. Проект выделен из панорамного приложения StereoPano и использует его стиль интерфейса, запись `.vr.jpg` и 7 языков (en, de, fr, it, es, ru, uk).

Идея в том, что две линзы телефона — это готовая стереопара с фиксированной базой (обычно 1–2 см). Снимать надо неподвижные сцены не ближе примерно 30 см: при меньшей дистанции разница между кадрами становится слишком большой. Для макро этот способ не подходит (см. раздел 8).

## 2. Как это работает

1. **Проверка камер (стартовый экран).** Приложение перебирает камеры телефона, находит «логические» камеры с несколькими физическими и показывает пары, которые можно попробовать. Для каждой физической камеры в отчёте: фокусное расстояние (и эквивалент 35 мм), размер сенсора, максимальный размер JPEG, минимальная дистанция фокуса, положение линзы относительно основной камеры (отсюда база между линзами) и тип синхронизации сенсоров.
2. **Съёмка.** Приложение открывает логическую камеру и создаёт одну сессию Camera2 с тремя потоками: превью и два JPEG, каждый привязан к своей физической камере. Один запрос даёт два снимка. Если телефон не принимает полное разрешение, пробуются 3264 и 2048 пикселей по длинной стороне.
3. **Обработка.**
   - Кадры поворачиваются по ориентации сенсора и повороту экрана.
   - Угол обзора выравнивается: у более широкой камеры берётся центральная часть по отношению эквивалентных фокусных расстояний.
   - Сопоставление блоков (нормированная корреляция) находит остаточные ошибки; по ним подгоняются вертикальный сдвиг, поворот и разница масштаба. Правый кадр исправляется.
   - Плоскость нулевого расхождения ставится на медиану по кадру, края обрезаются общей рамкой.
   - Левый и правый кадр определяются по положению линз и повороту экрана. Кнопка «Поменять Л/П» меняет их вручную.
4. **Сохранение** в `Pictures/StereoCam` (Android 10+ через MediaStore).

## 3. Форматы файлов

| Формат | Для чего |
|---|---|
| MPO (`.mpo`) | Стандартный формат 3D-фото (Fujifilm, Nintendo 3DS, 3D-телевизоры) |
| JPEG side-by-side | Левый и правый кадры рядом: VR-очки, картонные визоры |
| `.vr.jpg` | Для StereoPano Viewer на компьютере (правый кадр внутри расширенного XMP) |
| Красно-голубой анаглиф | Для очков с цветными фильтрами |
| Отдельные L/R JPEG | Для внешних редакторов |

По умолчанию включены MPO, side-by-side и автоматическое выравнивание. MPO сначала записывается с типом `image/mpo` в Pictures; если система не принимает этот тип, файл попадает в `Download/StereoCam`.

## 4. Установка

1. Откройте папку проекта в Android Studio (Hedgehog или новее).
2. Дождитесь синхронизации Gradle (если Studio предложит создать Gradle wrapper — согласитесь).
3. Подключите телефон (Android 9 или новее, `minSdk 28`) и нажмите Run.

## 5. Использование

1. Запустите приложение, разрешите доступ к камере.
2. Посмотрите, нашлись ли пары камер. Если нет — смотрите отчёт внизу экрана.
3. Выберите пару (по умолчанию первая — с наиболее близкими фокусными расстояниями, ею проще всего работать), выберите форматы, нажмите «Начать съёмку».
4. Держите телефон так, чтобы линзы были **на одной горизонтали**. Приложение само выбирает ориентацию экрана по расположению линз.
5. Нажмите кнопку затвора. Результат сохранится, внизу слева появится миниатюра.
6. Если эффект «вывернут» (близкое кажется далёким), нажмите «Поменять Л/П» и снимите снова.

## 6. Советы для хорошего стерео

- База фиксирована, поэтому дистанцию подбирайте под неё: хорошая стереопара — когда объект находится не ближе ~30× базы.
- Снимайте неподвижные сцены: две камеры синхронизированы не всегда идеально (тип синхронизации виден в отчёте: `calibrated` или `approximate`).
- Для пары «основная + сверхширокая» приложение обрезает широкий кадр по центру. Итоговое разрешение определяется более узкой камерой.
- Протирайте объективы, избегайте сцен без текстуры (чистое небо, белая стена): выравнивание опирается на детали изображения.

## 7. Совместимость: какие телефоны подходят

### 7.1 Требования

- Android 9 (API 28) или новее.
- Задняя «логическая мультикамера» как минимум с двумя физическими камерами.
- Телефон должен отдавать **физические камеры** сторонним приложениям и допускать **одновременную** съёмку с двух из них одной сессией.

### 7.2 Честный ответ: проверенного списка нет

**Надёжного публичного списка телефонов, на которых две физические камеры работают одновременно в стороннем приложении, не существует, и ни один телефон пока не проверен именно с StereoCam.** Причины:

- По документации Android физические камеры доступны приложениям с Android 9, но то, что показывает логическая камера, «полностью зависит от реализации производителя» (Camera HAL).
- Гарантирована только минимальная комбинация: **один YUV- или RAW-поток логической камеры можно заменить двумя потоками физических камер того же размера и формата.** Начиная с Android 10 логическая камера вообще не обязана поддерживать комбинации с физическими потоками.
- StereoCam использует **JPEG-потоки (возможно, разных размеров) и ещё превью** — такая комбинация **не входит в гарантии Android**. Это главный технический риск (см. раздел 9).
- Производители могут скрывать камеры или ломать сессию на отдельных прошивках.

### 7.4 Как проверить свой телефон

Установите приложение и откройте стартовый экран:

- **«Найдены пары»** — телефон показывает приложению две физические камеры (необходимое, но не достаточное условие).
- **«Нет подходящей пары»** — телефон не отдаёт физические камеры: StereoCam на нём не заработает.
- Дальше нужен реальный снимок. Если приложение пишет `Режим 1/2/3: …` и сохраняет файл — одновременная съёмка работает. Режим — это ступень разрешения (1 — максимум, 2 — до 3264, 3 — до 2048).
- Если пишет, что телефон отказывается запускать обе камеры, или что пришло только одно из двух изображений, — пара не подходит.

## 8. Ограничения

- Не проверено на телефоне ничего, что связано с Android: поиск камер, сессия с двумя физическими потоками, превью и его поворот, запись через MediaStore.
- Макро: фиксированная база линз (1–2 см) велика для объектов ближе ~30 см. Режим съёмки двумя кадрами и режим поворотного столика в проекте пока не реализованы.
- Автовыравнивание проверено только на синтетической паре. Реальные сцены (блики, повторяющиеся текстуры, мало деталей) могут дать неверную подгонку. Выравнивание можно отключить в настройках.
- Левый/правый определяется по положению линз; на телефоне без данных о положении принимается порядок «A — левый», поправить можно кнопкой.
- Память: фотографии ограничены 3600 пикселями по длинной стороне; приложение запрашивает увеличенную кучу.
- Переводы строк не вычитывались носителями языков.

## 9. Известные риски и следующие шаги

- **Комбинация потоков.** Надёжнее было бы использовать два потока `YUV_420_888` одинакового размера, затем самим кодировать JPEG; такая комбинация гарантирована Android 9 для устройств с физическими камерами. Превью для этого режима придётся брать из одного из потоков. Это вторая ступень, которую стоит добавить, если первая не заработает на вашем телефоне.
- Для Android 10+ можно заранее проверять комбинацию методом `CameraDevice.isSessionConfigurationSupported` и показывать результат на стартовом экране.
- На некоторых телефонах физические камеры не перечислены в `getCameraIdList()` (скрыты), но доступны по идентификатору; приложение обращается к ним напрямую.

## 10. Диагностика

| Сообщение | Значение |
|---|---|
| «Нет подходящей пары» | Телефон не отдаёт две физические камеры приложениям |
| «Телефон отказывается запускать обе камеры одновременно» | Сессия не настроилась ни в одном из трёх разрешений |
| «Телефон выдал только одно из двух изображений» | Второй кадр не пришёл за 9 секунд |
| «Не удалось открыть камеру» | Камера занята другим приложением или недоступна |
