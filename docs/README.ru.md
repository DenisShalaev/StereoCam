# StereoCam — документация (русский)

[English](README.en.md) · [Deutsch](README.de.md)

> **Статус: build 19.** По сообщению автора, приложение установлено и работает на Google Pixel 9. Подробные проверки отдельных функций (фокус по тапу, экспорт MP4, печать на растре, карта глубины на разных сценах) не проводились; у проекта нет Android SDK в среде сборки, поэтому автор собирает пакеты сам в Android Studio. Переводы строк не вычитывались носителями языков.

## 1. Что это

StereoCam делает стереофотографию **одним телефоном и одним нажатием**: снимает одновременно двумя задними камерами (например, основной и сверхширокоугольной), выравнивает пару и сохраняет в нескольких форматах. Проект выделен из панорамного приложения StereoPano и использует его стиль интерфейса, запись `.vr.jpg` и 7 языков (en, de, fr, it, es, ru, uk).

Идея в том, что две линзы телефона — это готовая стереопара с фиксированной базой (обычно 1–2 см). Снимать надо неподвижные сцены не ближе примерно 30 см: при меньшей дистанции разница между кадрами становится слишком большой. Для макро этот способ не подходит (см. раздел 8).

## 2. Как это работает

1. **Проверка камер .** Приложение перебирает камеры телефона, находит «логические» камеры с несколькими физическими и показывает пары, которые можно попробовать. Для каждой физической камеры в отчёте: фокусное расстояние (и эквивалент 35 мм), размер сенсора, максимальный размер JPEG, минимальная дистанция фокуса, положение линзы относительно основной камеры (отсюда база между линзами) и тип синхронизации сенсоров.
2. **Съёмка.** Приложение открывает логическую камеру и создаёт одну сессию Camera2 с тремя потоками: превью и два JPEG, каждый привязан к своей физической камере. Один запрос даёт два снимка. Если телефон не принимает полное разрешение, пробуются 3264 и 2048 пикселей по длинной стороне.
3. **Обработка.**
   - Кадры поворачиваются по ориентации сенсора и повороту экрана.
   - Угол обзора выравнивается: у более широкой камеры берётся центральная часть по отношению эквивалентных фокусных расстояний; затем это отношение сверяется по самим снимкам (поиск ±10 % сопоставлением изображений) и исправляется, если данные объектива неточны.
   - Сопоставление блоков (нормированная корреляция) находит остаточные ошибки; по ним подгоняются вертикальный сдвиг, поворот и разница масштаба. Правый кадр исправляется.
   - Плоскость нулевого расхождения ставится на медиану по кадру, края обрезаются общей рамкой.
   - Левый и правый кадр определяются по положению линз и повороту экрана. Кнопка «Поменять Л/П» меняет их вручную.
4. **Сохранение** в `Pictures/StereoCam` (Android 10+ через MediaStore).

### 2.1 Режим «со сдвигом» (одна камера)

Работает на **любом** телефоне, в том числе когда две камеры одновременно недоступны. Кнопка «Съёмка со сдвигом (одна камера)» в настройках (шестерёнка); если пар камер не найдено, она становится главной.

1. Ползунок «расстояние до объекта» (от 5 см до ~16 м) показывает, **на сколько сдвинуть телефон**: около 1/30 расстояния (например, 3 м → 10 см, 1 м → 3,3 см).
2. **Первый кадр** — левый глаз. После него блокируются экспозиция, баланс белого и (если телефон позволяет ручной фокус) фокус; оптическая и видеостабилизация выключаются, чтобы не «съедать» сдвиг.
3. На живое изображение накладывается **полупрозрачный первый кадр** («призрак»): сдвиньте телефон вправо, **не поворачивая**, и совместите картинки.
4. Строка «Поворот: наклон / разворот / крен» (датчик вращения) показывает отклонение от положения первого кадра. Зелёный — меньше 1°, жёлтый — меньше 2,5°, красный — больше.
5. **Второй кадр** обрабатывается тем же выравниванием и сохраняется в тех же форматах. «Заново» сбрасывает первый кадр. «Поменять Л/П» меняет направление: первый кадр становится правым глазом, двигать телефон нужно влево.

Честно о пределах: величину сдвига датчики телефона точно не измеряют — она на глаз по подсказке; движущиеся объекты (люди, ветки, вода) дают ошибки; выравнивание исправляет вертикальный сдвиг, наклон и масштаб, но не неверную базу. Режим не проверен на телефоне. Для макро (расстояние 5 см → сдвиг ≈ 1,7 мм) руками сдвиг не выдержать; для макро лучше поворотный столик — этого режима пока нет.

### 2.2 Быстрое переключение линз (по очереди)

Для телефонов, которые не отдают две камеры одновременно (нужен Android 11+). Кнопка «Быстрое переключение объективов» в настройках (шестерёнка); кроме того, приложение само переходит на этот режим, если сессия с двумя камерами не настроилась.

1. Открывается **одна сессия логической камеры**: превью и один JPEG-поток. Это стандартная комбинация, которую Android гарантирует.
2. Снимок делается первым объективом. Тут же зум переключается на второй объектив — так же, как это делает штатная камера. Коэффициенты зума вычисляются из эквивалентных фокусных расстояний относительно объектива, активного при зуме 1,0.
3. Приложение ждёт, пока в метаданных кадров (`ACTIVE_PHYSICAL_ID`) три кадра подряд не подтвердят, что работает второй объектив. Если не переключилось за 0,9 с, зум чуть подстраивается (до четырёх попыток).
4. Снимок вторым объективом, затем обычная обработка и сохранение. **Интервал между снимками в миллисекундах** показан в статусе.

Ограничения: интервал, скорее всего, составит сотни миллисекунд — движение объекта или руки даст ошибки, которые выравнивание не исправит (оно убирает вертикальный сдвиг, наклон и масштаб, но не параллакс от дрожания). Режим работает, только если логическая камера телефона переключает объектив зумом (так делают Pixel и многие другие, но не все). Не проверено на телефоне.

## 3. Форматы файлов

| Формат | Для чего |
|---|---|
| MPO (`.mpo`) | Стандартный формат 3D-фото (Fujifilm, Nintendo 3DS, 3D-телевизоры) |
| JPEG side-by-side | Левый и правый кадры рядом: VR-очки, картонные визоры |
| `.vr.jpg` | Для StereoPano Viewer на компьютере (правый кадр внутри расширенного XMP) |
| Красно-голубой анаглиф | Для очков с цветными фильтрами |
| Отдельные L/R JPEG | Для внешних редакторов |

По умолчанию включены MPO, side-by-side и автоматическое выравнивание. MPO сначала записывается с типом `image/mpo` в Pictures; если система не принимает этот тип, файл попадает в `Download/StereoCam`.

## 4. Установка

1. Откройте папку проекта в Android Studio (Hedgehog или новее).
2. Дождитесь синхронизации Gradle (если Studio предложит создать Gradle wrapper — согласитесь).
3. Подключите телефон (Android 9 или новее, `minSdk 28`) и нажмите Run.

## 5. Использование

1. Запустите приложение, разрешите доступ к камере: сразу откроется изображение камеры.
2. При необходимости откройте настройки (шестерёнка): режим съёмки, пара камер (по умолчанию — с наиболее близкими фокусными расстояниями), форматы файлов, отчёт о камерах.
3. Тапом по экрану сфокусируйтесь на нужном объекте (вертикальный ползунок — ручной фокус).
4. Держите телефон так, чтобы линзы были **на одной горизонтали**. Приложение само выбирает ориентацию экрана по расположению линз.
5. Нажмите кнопку затвора. Результат сохранится, внизу слева появится миниатюра.
6. Если эффект «вывернут» (близкое кажется далёким), нажмите «Поменять Л/П» и снимите снова.

### 5.1. Галерея и просмотр в движении

Миниатюра слева внизу на экране камеры открывает галерею со списком снимков из Pictures/StereoCam и Download/StereoCam (MPO, .vr.jpg, SBS) либо любой файл через «Открыть файл…». Выбранная стереопара показывается как движение камеры на обычном экране: от левого глаза к правому и обратно, с плавным торможением на концах (синусоида). Пути: «Туда-обратно» или «Вокруг объекта» (добавляется вертикальная составляющая — кружение). Размах задаётся кратно реальной базе (×1…×6), скорость — три ступени, касание картинки — пауза.

**Сколько градусов это на самом деле.** Реальная параллакс-база между двумя камерами телефона — около 1–2,5 см, поэтому угол между видами ≈ arctan(база / расстояние): при базе 2 см около 1° на 1 м, ≈2,3° на 0,5 м, ≈3,8° на 0,3 м. Для сдвига на 20–30° нужно в 5–10 раз больше базы, чем даёт телефон. Такие виды программа **достраивает** по карте глубины (она считается из самой стереопары на ~480 px); чем больше размах, тем заметнее артефакты на краях предметов (участки, которых не видела ни одна камера, заполняются фоном). Практический предел — примерно ×4–×6 от реальной базы (≈10–15° на близких планах); для этого размаха и сделан выбор ×1…×6.

**Честно:** карта глубины оценивается по двум изображениям от разных объективов, на однотонных поверхностях и бликах она неточна; расчёт идёт на процессоре, на телефоне порядка нескольких кадров в секунду (проверен только алгоритм на ПК, на устройстве не запускался). Анимацию можно сохранить как GIF или MP4 (раздел 5.5). Ползунок «Сила глубины» уменьшает или усиливает смещение пикселей, если карта глубины на каких-то участках ошибается.

Карта глубины для режима «Движение» считается методом полуглобального сопоставления (SGM, census-стоимость, допуск ±1 пиксель по вертикали), диапазон выбирается по самому снимку; узкие полосы с выбивающейся глубиной отбрасываются и заполняются из окружения.

### 5.2. Запуск, настройки и галерея

Программа сразу открывается с изображением камеры (режим выбирается автоматически: две камеры, если телефон их отдаёт, иначе съёмка со сдвигом). Шестерёнка справа вверху открывает настройки: режим съёмки (авто / две камеры / быстрое переключение / сдвиг), выбор пары камер, форматы файлов, выравнивание и отчёт. Миниатюра последнего снимка слева внизу открывает галерею. В галерее: касание — просмотр в движении; долгое нажатие — выделение нескольких файлов (отправить, конвертировать в SBS / анаглиф / отдельные L и R / MPO, удалить). Конвертация создаёт новые файлы, оригиналы не меняются; удаление необратимо (на Android 11+ система может запросить подтверждение).

### 5.3. Режимы просмотра (как в StereoPano)

Верхняя панель круглых кнопок такая же, как в StereoPano: назад, режим, пауза и настройки движения (только в режиме «Движение»), сохранение анимации, печать на растре, гироскоп, половинный SBS (только в режиме SBS), коррекция линз (только в Cardboard), сброс масштаба, настройки. Кнопка режима переключает по кругу: **Движение** → **2D** → **Cardboard** (два глаза рядом, ландшафт, мягкая бочкообразная коррекция) → **SBS-очки** (полный или «половинный» — каждый глаз занимает свою половину экрана). Двойное касание — 2D ↔ последний стерео-режим; щипок — масштаб; касание — показать/скрыть панель. Гироскоп сдвигает увеличенное изображение при наклоне телефона (грубая оценка: 60° ≈ ширина кадра).

Честно: коррекция линз — приблизительная, под конкретные очки не калибровалась; на устройстве не проверялось.

В просмотре переход к следующему / предыдущему файлу галереи — свайпом вверх / вниз (когда нет увеличения) или клавишами громкости (вниз — следующий, вверх — предыдущий). Стрелка «назад» слева вверху возвращает в галерею.

### 5.4. Фокус при съёмке

Тап по экрану камеры фокусируется и замеряет экспозицию на этом месте (в круге на экране). Вертикальный ползунок справа настраивает расстояние вручную: вверху — бесконечность, внизу — ближняя граница объектива; метка «AF» возвращает автофокус. Ползунок показывается, только если объектив умеет менять фокус. При съёмке двумя камерами настройка передаётся логической камере и действует на обе линзы настолько, насколько телефон это позволяет; в режиме со сдвигом после первого снимка фокус блокируется для второго. Отдельно на устройстве не проверялось.

### 5.5. Экспорт анимации и сила глубины

Кнопка с клапперной плёнкой в режиме «Движение» (и пункты «Конвертировать» в галерее) сохраняет движение как **анимированный GIF** (Pictures/StereoCam, ширина до 480 px, один цикл) или **видео MP4** (Movies/StereoCam, до 720 px, два цикла, H.264). Используются текущие настройки: размах, скорость, траектория и сила глубины. Ползунок «Сила глубины» (0–150 %) сжимает или усиливает смещения пикселей относительно плоскости фокуса: если на некоторых участках смещение слишком большое или карта глубины ошибается, уменьшите значение (0 % — картинка движется как плоская, без параллакса). GIF ограничен 256 цветами; MP4 кодируется аппаратным кодеком телефона и на устройстве не проверялся.

### 5.6 Печать на растре (лентикулярная)

Кнопка принтера в просмотре (или «Конвертировать → Печать на растре…» в галерее для одного выбранного файла) открывает подготовку изображения для печати под линзовый растр: из пары L/R строится N ракурсов (8–24), которые чередуются полосами по шагу линз (DPI / LPI). Настраиваются окно кадра (перетаскивание и щипок), растр 75 или 100 LPI, реальный LPI по тестовому листу, формат A4/A5/A6, ориентация, DPI, число ракурсов, сила глубины, метки совмещения и реверс. Результат — PNG с заданным DPI в Pictures/StereoCam/Lenticular. Режим перенесён из StereoPano; на реальной печати и на устройстве не проверялся.

### 5.7 Плоскость экрана

Ползунок внизу просмотра (скрывается вместе с панелью кнопок) задаёт, какая глубина находится «в плоскости экрана». По умолчанию в плоскость экрана ставится главный объект (медиана расстояний в центре кадра, по карте глубины); ползунок вправо отодвигает всю сцену за экран, влево — выводит предметы вперёд, «в воздух» перед экраном. Диапазон ±6 % ширины кадра; тап по подписи — сброс. Действует в режимах «Движение» (неподвижная глубина), Cardboard и SBS; при смене файла сбрасывается. Файлы не меняются, настройка действует только на просмотр и на экспорт GIF/MP4 текущего файла. Из-за сдвига по краям может остаться узкая чёрная полоска. Реальное расстояние до предмета приложение не показывает: оно известно только в момент съёмки и в файл не записывается. Не проверено на устройстве.

### 5.8 Помощь при компоновке кадра

На экране съёмки справа под шестерёнкой две кнопки. **Сетка** переключает: выкл. → правило третей → золотое сечение (линии на 38,2 % и 61,8 %). **Уровень горизонта** показывает по датчику ускорения линию, которая поворачивается вместе с наклоном телефона: жёлтая — наклон меньше 5°, зелёная — меньше 1°; работает и в портрете, и в ландшафте. Вверху экрана показывается расстояние фокуса (по ответам камеры); предметы ближе точки фокуса при просмотре выходят перед экраном, дальше — уходят за экран (если главный объект поставлен в плоскость экрана, см. 5.7). Если фокус ближе примерно 15 баз (по умолчанию ≈30 см), показывается предупреждение. Честно: в живом превью нет карты глубины, поэтому линий «что выйдет за экран» по каждому месту кадра нет, только расстояние фокуса; не все телефоны отдают расстояние фокуса приложению. Не проверено на устройстве.

## 6. Советы для хорошего стерео

- База фиксирована, поэтому дистанцию подбирайте под неё: хорошая стереопара — когда объект находится не ближе ~30× базы.
- Снимайте неподвижные сцены: две камеры синхронизированы не всегда идеально (тип синхронизации виден в отчёте: `calibrated` или `approximate`).
- Для пары «основная + сверхширокая» приложение обрезает широкий кадр по центру. Итоговое разрешение определяется более узкой камерой.
- Протирайте объективы, избегайте сцен без текстуры (чистое небо, белая стена): выравнивание опирается на детали изображения.

## 7. Совместимость: какие телефоны подходят

### 7.1 Требования

- Android 9 (API 28) или новее.
- Задняя «логическая мультикамера» как минимум с двумя физическими камерами.
- Телефон должен отдавать **физические камеры** сторонним приложениям и допускать **одновременную** съёмку с двух из них одной сессией.

### 7.2 Честный ответ: проверенного списка нет

**Надёжного публичного списка телефонов, на которых две физические камеры работают одновременно в стороннем приложении, не существует, и ни один телефон пока не проверен именно с StereoCam.** Причины:

- По документации Android физические камеры доступны приложениям с Android 9, но то, что показывает логическая камера, «полностью зависит от реализации производителя» (Camera HAL).
- Гарантирована только минимальная комбинация: **один YUV- или RAW-поток логической камеры можно заменить двумя потоками физических камер того же размера и формата.** Начиная с Android 10 логическая камера вообще не обязана поддерживать комбинации с физическими потоками.
- StereoCam использует **JPEG-потоки (возможно, разных размеров) и ещё превью** — такая комбинация **не входит в гарантии Android**. Это главный технический риск (см. раздел 9).
- Производители могут скрывать камеры или ломать сессию на отдельных прошивках.

### 7.4 Как проверить свой телефон

Установите приложение и откройте настройки (шестерёнка):

- **«Найдены пары»** — телефон показывает приложению две физические камеры (необходимое, но не достаточное условие).
- **«Нет подходящей пары»** — телефон не отдаёт физические камеры: режим двух камер недоступен, пользуйтесь режимом «со сдвигом» (раздел 2.1).
- Дальше нужен реальный снимок. Если приложение пишет `Режим 1/2/3: …` и сохраняет файл — одновременная съёмка работает. Режим — это ступень разрешения (1 — максимум, 2 — до 3264, 3 — до 2048).
- Если пишет, что телефон отказывается запускать обе камеры, приложение само переходит на быстрое переключение линз (раздел 2.2). Если пришло только одно из двух изображений — пара не подходит для одновременной съёмки, попробуйте режим 2.2.

## 8. Ограничения

- Приложение проверено автором только на Google Pixel 9 (запускается и работает); на других телефонах поведение камер (две физические камеры одновременно, быстрое переключение) может отличаться. Подробности по отдельным функциям — экспорт MP4, печать на растре, ручной фокус — отдельно не подтверждены.
- Карта глубины для режима «Движение» на реальных сценах может ошибаться (блики, однотонные поверхности); для этого есть ползунок «Сила глубины».
- Макро: фиксированная база линз (1–2 см) велика для объектов ближе ~30 см. Режим «со сдвигом» есть (раздел 2.1), но для макро сдвиг в миллиметры руками не выдержать; режим поворотного столика пока не реализован.
- Автовыравнивание проверено только на синтетической паре. Реальные сцены (блики, повторяющиеся текстуры, мало деталей) могут дать неверную подгонку. Выравнивание можно отключить в настройках.
- Левый/правый определяется по положению линз; на телефоне без данных о положении принимается порядок «A — левый», поправить можно кнопкой.
- Память: фотографии ограничены 3600 пикселями по длинной стороне; приложение запрашивает увеличенную кучу.
- Переводы строк не вычитывались носителями языков.

## 9. Известные риски и следующие шаги

- **Запасные режимы.** Если одновременная съёмка не работает, есть быстрое переключение линз (2.2) и сдвиг одной камерой (2.1).
- **Комбинация потоков.** Надёжнее было бы использовать два потока `YUV_420_888` одинакового размера, затем самим кодировать JPEG; такая комбинация гарантирована Android 9 для устройств с физическими камерами. Превью для этого режима придётся брать из одного из потоков. Это вторая ступень, которую стоит добавить, если первая не заработает на вашем телефоне.
- Для Android 10+ можно заранее проверять комбинацию методом `CameraDevice.isSessionConfigurationSupported` и показывать результат на стартовом экране.
- На некоторых телефонах физические камеры не перечислены в `getCameraIdList()` (скрыты), но доступны по идентификатору; приложение обращается к ним напрямую.

## 10. Диагностика

| Сообщение | Значение |
|---|---|
| «Нет подходящей пары» | Телефон не отдаёт две физические камеры приложениям |
| «Телефон отказывается запускать обе камеры одновременно» | Сессия не настроилась ни в одном из трёх разрешений |
| «Телефон выдал только одно из двух изображений» | Второй кадр не пришёл за 9 секунд |
| «Не удалось открыть камеру» | Камера занята другим приложением или недоступна |
